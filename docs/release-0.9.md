# Tanutsuna Studio 0.9.6 — 録画・ライブ配信・編集

## 最初の画面

「録画する」「ライブ配信する」「編集する」の3つから始めます。企画は必須ではありません。企画・メモ、作品一覧、素材は左側の補助メニューに移しました。「録画する」は日時の作品と保存先を自動作成し、従来の1080p/50fps録画へ進みます。

## ライブ配信

1. Minecraftなど、配信するゲームのウィンドウを選びます。「ウィンドウを更新」で起動したゲームを探せます。
2. URLとキーを入力し、「YouTubeへ配信開始（自動準備）」を押します。ゲーム画面・V体カメラ・音声を自動で起動し、準備完了後にYouTubeへ接続します。プレビュー操作は必須ではありません。初回はOSの画面収録・カメラ・マイク許可を確認してください。顔が見えていなくても開始できます。
3. 事前に映像を確認したい場合だけ「映像を確認」を押します。V体の位置と大きさ、PC全体・マイク・BGM・効果音の音量を調整できます。PC全体には通知と他アプリの音も含まれます。マイクを使う場合はヘッドホンを推奨します。
4. BGMは複数MP3を候補として選び、1曲を選択して再生できます。BGMは繰り返します。効果音はファイルを選んで流します。ソフト内音声は配信用ミックスに流れ、スピーカーへは重ねて出力しません（ループバックとの二重取り込みを避けます）。
5. YouTube Studioで配信枠・公開範囲を設定し、表示されたストリームURLとストリームキーを登録します。URLの方式はそのまま使用します。RTMPは暗号化されません。暗号化する場合はStudioの鍵アイコンからRTMPS URLを表示して使ってください。キーは伏せ字です。保存する場合はMacのキーチェーン／Windowsの資格情報マネージャーを使い、作品や設定JSONには書きません。
4. 接続中・送信中・再接続中、経過時間と音量メーターを表示します。「停止」で終了します。キー付きストリームURLをURL欄へ貼り付けても使えます。

映像は選択したウィンドウだけです。消失時は待機映像を表示し、画面全体へ勝手に切り替えません。別のウィンドウを使う場合は手動で選び直します。OSのウィンドウキャプチャに対応しない排他的フルスクリーン等では、ゲームをウィンドウ／ボーダーレス表示で使用してください。

ライブ映像は60fps固定で、軽量720pまたは標準1080pを選びます。H.264ハードウェアエンコーダーを優先し、使えなければCPUへ切り替えます。仮想カメラ・OBSの別途インストールは不要です。YouTubeアカウント連携やコメント表示はありません。実フレームレートはゲーム・PC性能・回線に左右され、負荷が高いと60fpsを維持できない場合があります。

## 0.9.6の修正

- ライブ映像・ウィンドウ取得・合成・配信エンコード・同時録画を60fpsに統一しました。カメラの顔追跡は負荷を抑えて最大30fpsです。
- 720p60を6Mbps、1080p60を12Mbpsに設定しました。YouTubeのH.264推奨範囲内です。

## 0.9.5の修正

- 0.9.4までにRTMP URLをRTMPSへ自動変換していた処理を修正。Studioに表示されたプロトコルを保持します。既定のRTMP URLをRTMPSへ変換した保存値は、Studio標準のRTMP URLへ戻します。
- Apple TLSの `-9806` はTLS接続がエラー終了したことを示します。RTMPSを選ぶ場合は、Studioの鍵アイコンから表示したRTMPS URLを使用してください。
- 接続の詳細を成功接続まで画面に残し、ボタンからコピーできるようにしました。

## 0.9.4の修正

- YouTube RTMPSの接続タイムアウトを15秒へ延長し、再接続が続く場合はキーを伏せた通信エラー詳細を表示します。

## 0.9.3の修正

- エンコード遅延の通知を5秒ごとに制限し、通知イベントで画面入力まで詰まる問題を修正しました。
- YouTube接続状態と映像負荷を別々に表示し、負荷表示で接続エラーが隠れないようにしました。

## 0.9.2の修正

- 配信開始要求を先に保持するよう変更。初回のマイク許可後も自動準備を続け、プレビューを先に手動起動する必要をなくしました。
- ライブ操作画面の映像取得・合成を15fpsに抑え、UI入力の応答性を改善しました（0.9.6で60fpsへ変更）。
- 接続状態を「YouTubeへURLとキーを送信中」「接続できず自動再接続中」など、次に確認する項目が分かる表示に変更しました。

## 同時に録画する場合

初期状態では録画はオフです。オンにすると日時付きの作品へ、ゲーム映像・PC音・マイク・BGM・効果音・V体の動きを分離して保存します。配信と同じ解像度・60fpsです。V体は終了後に透過映像へ変換し、全素材を同期して編集へ配置します。元の音声ファイルを保持し、ゲーム映像へV体を焼き込みません。

送信と録画は独立しており、ネット切断時は送信を再接続しながら録画を継続します。停止操作の後は再接続しません。保存・変換に失敗した場合も元データを保持し、録画一覧から整理・映像化を再開できます。長時間の録画では空き容量が必要です。

## 確認済みと未確認

- Macの実ウィンドウ取得＋GPUのV体合成を、テスト用ウィンドウで確認。ローカルに合成映像72フレームを保存・再生しました。本人のカメラやMinecraft本体を使った確認ではありません。
- ローカルRTMP受信を意図的に切断し、再接続、録画継続（約10.7秒）、停止後の再接続抑止を確認。
- MacのPC音ヘルパー起動・PCM取得、OSキーチェーンの保存・読出し・削除を確認。検証用のキーを使い、実際のストリームキーは使用していません。
- 配信エンコード・4系統の分離音声保存・編集への配置／重複防止、既存録画と企画保存の対象テストを確認。

**実際のYouTube RTMPS／限定公開配信、Windows実機、本人のカメラ・マイクを含む通し操作、長時間・低スペック機の性能は未確認です。** 配布物が作成できたことを、YouTubeでの本配信成功や不具合ゼロの保証として扱わないでください。MacはApple Silicon/macOS 15以降向け・未公証、WindowsはWindows 11 x64向け・未署名です。

## 0.9.1の修正

- V体・録画・配信のカメラ選択を共通化し、追跡中の選択変更も再接続へ反映します。カメラ画面には起動時に一覧を表示します。
- Mac版に専用ウィンドウ取得ヘルパーを必ずビルド・同梱します。Java/Minecraftやタイトルのないウィンドウを列挙し、WindowsはQt一覧から漏れたウィンドウの互換取得を追加します。排他的フルスクリーンや最小化では取得できない場合があるため、ウィンドウ／ボーダーレスで確認してください。
- YouTubeのRTMP/RTMPS URLとキー付きURLに対応します。URLと別入力のキーが異なる場合は開始前に説明します。視聴URLを貼った場合も区別して案内します。手入力したキーが保存済みのキーで上書きされる問題も修正しました。
- 接続失敗を表示し、単に送信できた状態を「公開配信中」とは表示しません。公開状態はYouTube Studioで確認してください。
- 初期解像度720p、V体描画15Hz、プレビューとメーター5Hz、カメラ入力上限20fps。配信・同時録画の30fpsは維持します。静止したウィンドウの同じ画面をMacヘルパーから繰り返し転送しません。

確認：74件の自動テスト、模擬カメラの選択・再接続・停止と顔推論、実際のJavaウィンドウの検出・1280×720キャプチャ、ローカルRTMPの切断・再接続と録画継続。Windows実機とMinecraft本体の描画、実際のYouTube公開配信は未確認です。

配信先の仕様：[YouTube公式RTMPS案内](https://support.google.com/youtube/answer/10364924?hl=ja)。Windows互換取得：[FFmpeg公式gdigrab仕様](https://ffmpeg.org/ffmpeg-devices.html#gdigrab)。
