# たぬつな 制作デスク / Cut Raft 0.9.14

画面収録、YouTubeライブ配信、V体、企画・メモ、編集を動画ごとのフォルダで管理するネイティブアプリです。元のCut Raftプロジェクトは変更しません。

V体はユーザー提示のサングラス姿に更新しました。手足・鼻はなく、目はUVテクスチャで固定、口のみ動かします。あいうえお別に横幅・開いた時の高さを調整でき、口の線の太さも変更できます。立体的な耳と口腔、薄いゴーグルフレームと凸面レンズ、アウトライン、3段階のトゥーン描画を使用し、顔の向き・移動の追従倍率を調整できます。[モデルと操作の詳細](docs/tanuki-model.md)

カメラ追跡ではOSのカメラ許可と、カメラ・マイク同時使用の許可種別に対応し、起動エラーの原因も表示します。唇の形に加え、ローカルマイクの音量でも発話中の細かな口の動きを補います。音声は端末内で処理し、感度と使用マイクはカメラトラッカー内で選べます。

## 起動

- Windows 11 x64：`dist/Tanutsuna-Studio-Windows11-x64.zip` をすべて展開し、`Tanutsuna Studio.exe` を起動します。`app` と `runtime` を同じ場所に置いてください。
- Mac検証版（Apple Silicon / macOS 15以降）：`dist/Tanutsuna Studio.app` を開きます。

配布版にPythonの追加インストールは不要です。Mac版は未公証です。

## はじめる

最初の画面は「録画する」「ライブ配信する」「編集する」の3つです。企画は必須ではありません。「企画・メモ」「作品一覧」は補助メニューから開けます。

- 録画する：日時付きの作品と保存先を自動作成し、画面全体の1080p/50fps録画へ進みます。停止後に画面・PC音・マイク・透過V体を保存し、編集へ同期配置します。
- ライブ配信する：選択したゲームのウィンドウにV体を重ね、PC全体・マイク・BGM・効果音を調整してYouTubeへ直接送信します。映像は60fps固定。初期設定は軽量720p、1080pも選べます。同時録画は任意で初期オフです。
- 編集する：保存した作品を選び、編集を続けます。「自動編集」からローカルAI文字起こし、仮テロップ配置、無音カット、音の役割・全体音量・BGM選択を使えます。音量は最大500%まで調整できます。文字起こし結果は確認・修正してから配置でき、字幕を選んで保存済みデザインへ一括変更できます。

編集画面のタイムラインは「メイン」レイヤーから始まり、動画・静止画・音声を置けます。追加した映像レイヤーは上側、音声レイヤーは下側に並びます。字幕は「字幕ライブラリ」でSRTを動画ごとに保存でき、保存済みを選択または一括でタイムラインへ追加できます。文字起こしはPC内で処理し、AIモデルは初回だけ選択して取得します。テロップの大きさ・角度・位置はスライダーで調整できます。

ストリームキーはOSの資格情報ストアへ任意で保存します。配信枠と公開範囲はYouTube Studioで設定します。操作手順・確認範囲は [0.9.6 ご利用ガイド](docs/release-0.9.md) を参照してください。

## アプリの更新

設定画面で最新版を確認できます。起動時にもGitHub Releasesをバックグラウンドで確認します。更新ZIPはサイズ・SHA-256・ZIP構成・アプリ版数を検証してから一時領域へ展開します。ダウンロード・検証・展開の進捗を％で表示します。Macアプリは既存アプリの場所を保ったまま内部を安全に入れ替え、更新版の起動を確認できた場合だけ旧版を削除します。更新版が起動しない場合は前の版へ戻します。録画・配信・素材処理・編集の保存が終わるまでは更新を開始しません。作品、収録素材、設定はアプリ本体とは別のユーザーデータ領域に保存されます。詳細は [0.9.17 ご利用ガイド](docs/release-0.9.17.md) を参照してください。

自動更新配布物はGitHubのReleasesに、`Tanutsuna-Studio-macOS-arm64.zip` と `Tanutsuna-Studio-Windows11-x64.zip` の名前で版数付きタグ（例：`v0.9.17`）とともに登録します。`main`はソースコード用で、アプリはReleaseから取得します。

Macでは同梱の [`最新版を取得してビルド.command`](最新版を取得してビルド.command) をダブルクリックすると、GitHubからソース取得・Macアプリ作成・Windows配布ZIP作成を選んで実行できます。ソースに未保存の変更がある場合は安全のため停止します。Releaseへの公開はこの操作には含みません。

## 単独録画の補足

収録中は一時領域を使い、停止後は変換より先に収録済みデータを動画内へ保存します。準備の中止分は破棄します。収録開始後の失敗・保存中断では元データを保持し、再度その動画を開くと復旧可能な収録を一覧に表示します。編集データ用フォルダがなくなった場合は、残っている完成済みの収録から編集画面を再構成できます。

素材・収録は一覧の削除ボタン、または右クリックからゴミ箱へ移せます。素材を削除すると編集内の配置も外れます。OSで素材ファイルやフォルダを消した場合も、一覧と編集中の参照を更新します。

V体は録画の上に焼き込みません。収録中は約25Hzの軽い動きデータのみを保存し、終了後に1080×1080・収録と同じfpsの透過MOV（PNG可逆圧縮）へ変換します。1080pxのGPU描画と4x MSAAで輪郭を滑らかに保ち、完成映像と同じ解像度で作ることで保存時の負荷を減らします。緑背景のキー処理は不要で、右下へ配置します。画面録画と別々にカット、移動、サイズ調整ができます。顔カメラの動画自体はV体素材に含めません。

収録は設定したディスプレイ全体です。PC音にはゲーム以外のアプリや通知も含みます。マイクがスピーカーの音を拾う場合はヘッドホンを使ってください。

## 軽量化の構成と限界

- MacはScreenCaptureKitのGPU画面サーフェスとVideoToolboxのハードウェアH.264を優先。WindowsはQtのネイティブ画面収録と利用可能なハードウェアエンコーダーを使用します。
- WindowsのPC音はWASAPIループバックです。仮想オーディオケーブルやOBSは不要です。初回にWindows標準の.NET Frameworkコンパイラで小さな音声ヘルパーを準備します。
- 収録中は編集プレビューと新しいサムネイル生成を止めます。V体の追加動画エンコードを同時に実行しません。
- 終了後のMP3変換、V体変換は直列処理です。動画・音声をアップロードしません。
- エフェクトとテロップ生成はUIから分離し、要求とキャッシュを上限内に保ちます。

**1080p・50fpsは固定の収録設定です。低スペックPCでゲームと同時に常に50fpsを維持できる保証はありません。** エンコーダー、GPUドライバー、ゲームの負荷、ディスク速度に依存します。欠落や目標fpsとの差を検出した場合は収録一覧の下に表示します。Windowsの音声同期は最初のバッファ到着時刻による推定です。MacではScreenCaptureKitのサンプル時刻を使用します。長時間のドリフトと低スペックWindows実機の性能は未検証です。

V体の映像化には収録時間に応じた待ち時間があります。全素材の保存処理中は終了を待機します。手動の作り直しを中断した場合も元データを保持し、一覧から再開できます。

## 保存と再開

初期保存先はドキュメント内の `TanutsunaStudio`。各動画は固有IDを持ちます。同じタイトルでも混ざりません。

```text
動画ID/
  project.json
  00-plan/plan.json          予定・自由メモ・ペンボード・概要
  01-recordings/収録日時-ID/
    take.json                状態・時刻・素材一覧・処理状況
    screen.mp4               画面映像
    desktop.mp3              ゲーム・PC音
    voice.mp3                マイク
    vtuber-motion.jsonl      V体の動き（有効時）
    vtuber.mov               V体の独立した透過映像（変換後）
    *-source.wav / .m4a       中間音声・復旧用
    *.log                    エラー調査用
  02-assets/
  03-edit/main.cutraft
  04-exports/
```

収録情報と設定は一時ファイルから置き換えて保存します。準備を中止した分は一時領域から破棄します。収録開始後の異常終了分は復旧用に保持します。完成済みの画面映像・音声は、V体変換に失敗しても保持します。収録一覧の「V体を高画質・透過で作り直す」で変換し直せます。旧MP4から更新する場合も、既存の配置・サイズを引き継ぎます。透過素材は旧MP4より容量が増えます。

## 開発と再ビルド

```sh
python3 scripts/build_native.py --prepare-only
"/Users/Raft/Documents/Cut Raft/.venv/bin/python" run.py
"/Users/Raft/Documents/Cut Raft/.venv/bin/python" -m unittest discover -s tests -p 'test*.py' -v
python3 scripts/build_native.py
"/Users/Raft/Documents/Cut Raft/.venv/bin/python" scripts/build_mac.py
```

`CUTRAFT_SOURCE` で元のCut Raftの場所を指定できます。修正は `studio/` と `editor_overrides/` に保持し、再ビルド時に複製側へ適用します。MacビルドにはSwiftとPyInstallerが必要です。Windowsランタイムとライセンスを保持し、配布物のソースハッシュを記録します。

検証内容と制約は [docs/recording-0.4.md](docs/recording-0.4.md) を参照してください。

保存と口形の改訂内容・操作は [0.6 ご利用ガイド](docs/release-0.6.md) を参照してください。

## 自動編集・音量・BGM

編集画面の「自動編集」またはツールバーから、無音の全トラック同期カット、音の役割指定、全体音量、MP3候補からのBGM選択を開けます。操作と適用範囲は [0.8 ご利用ガイド](docs/release-0.8.md) を参照してください。

企画一覧に収録予定・概要の有無を表示し、ダブルクリックで企画の段階に合った画面へ進めます。文字起こしのモデル・実行エンジンは配布物から除外しました。
